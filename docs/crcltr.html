Effect CRCLTR

s3g Effect CRCLTR is a stereo-input, stereo-output dual looper. It is the first desktop revision of the CRCLTR v1.0.1 Gen/Oopsy firmware for Noise Engineering Versio hardware.

The CLAP adapter and looper are separate. The effect implementation lives in the portable s3g_crcltr.h DSP core, with no CLAP dependency, so desktop listening and DSP revisions can feed a later Daisy/Versio adapter.

Workflow

  1. Choose Loop 1, Both, or Loop 2 with Record Target.
  2. Set Record to RECORD and hold it for the desired capture time.
  3. Return Record to Idle to close the loop and restart its playhead.
  4. Use Xfade Type and Xfade to move between the two loop engines.
  5. Use Blend for the equal-power source/loops mix.

A record hold shorter than 100 ms is discarded without changing an existing loop. The first 100 ms is kept in a pre-roll buffer, so a valid hold retains its beginning.

Two Loop Engines

Loop 1: seamless

As in CRCLTR v1.0.1, Loop 1 uses the first half of the captured audio. Hold Record for twice the intended loop duration. A 10 ms equal-power seam crossfade gives a maximum playback loop of about 16 seconds from the 32-second capture memory.

Loop 2: groove duck

Loop 2 uses the full captured duration. A raised-cosine 250 ms edge window ducks the start and end to suppress clicks and make the seam pulse. Its maximum loop duration is about 32 seconds.

Hardware-Target Boundary

  • The process path has fixed capacity and performs no allocation.
  • Desktop builds let the core own four 32-second loop channels and four 100 ms pre-roll channels.
  • A Daisy adapter can pass caller-owned buffers through CrcltrMemory, placing the large loop channels in external SDRAM.
  • At 48 kHz, the loop channels use 23.44 MiB and the pre-roll channels use 75 KiB.
  • Rates, timing constants, and recording behavior are sample-rate aware rather than fixed to the original 48 kHz sample counts.

First-Port Boundaries

  • The CLAP currently uses the host's generic parameter view; a custom s3g effect GUI is not part of this first port.
  • CLAP state stores parameters only. Recorded audio is intentionally not serialized into the project state yet.
  • Short record taps are non-destructive, improving on the original delayed record gate.
  • The sine and trapezoid crossfade rates have an explicit 0.25x-to-4x mapping tied to Loop 1 timing.
