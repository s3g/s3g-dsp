Drum Overload

Drum Overload is a stereo, zero-latency distortion processor voiced for synthesized drums. A linked transient detector controls density and punch before a two-times nonlinear core; low-band preservation, tone, wet/dry mix, and output trim complete the path.

This effect is currently a source-build preview. Build it with -DS3G_BUILD_CLAP_PLUGIN=ON -DS3G_BUILD_DRUM_OVERLOAD_PREVIEW=ON, or as part of S3G_BUILD_FUTURE_COMPONENTS.

Workflow

  1. Insert s3g Drum Overload after a drum instrument or stereo drum bus.
  2. Route the processed track to the main stereo output or a headphone monitor.
  3. Choose a CIRCUIT, raise OVR, and use INPUT to set how strongly the drum reaches the nonlinear core.
  4. Balance DENS and bipolar PUNCH while listening to both the body and first transient.
  5. Restore low weight, set breakup and tone, then compare with MIX, OUT, and BYP.

Signal Flow

  1. The stereo input enters linked fast and slow envelope followers. LINK blends independent and shared detection without passing audio between channels.
  2. DENS pushes sustained body toward the circuit threshold. Positive PUNCH emphasizes detected attacks; negative values crush them.
  3. WEIGHT removes a clean portion of the sub-210 Hz input before overload and returns it afterward.
  4. The remaining signal enters the selected two-times oversampled circuit, followed by tone shaping and DC removal.
  5. MIX blends clean and processed audio before OUT. BYP returns the input directly.

Stereo and Low-End Behavior

The audio lanes remain separate throughout the processor. LINK only shares detector behavior: higher settings make left and right density changes agree more closely without narrowing the image. WEIGHT preserves part of the clean sub-210 Hz band, allowing kick and tom fundamentals to remain stable while upper shells, wires, rims, and cymbal energy drive the selected circuit.

Presets and State

The title starts at INIT. LOAD and SAVE exchange complete user preset states; the effect does not provide a factory bank or a random button. All thirteen controls are automatable and saved in CLAP state.

Limits

Drum Overload requires a two-channel input and output. It does not synthesize audio, accept MIDI, or introduce reported host latency. Its internal two-times nonlinear core is anti-aliased with causal filters, so “zero latency” means no additional host-compensated delay rather than a mathematically phase-neutral process.
