Sample Instruments

The Sample family uses loaded or captured audio as an instrument source. Sample Player handles one-shots and loops, Sample Doubles puts two independently positioned copies of one stereo source behind a performance crossfader, Sample Wavesets plays zero-crossing groups, Sample Motion combines bounded trajectories with realtime segment events, Sample Lanes draws one read path across four files, Sample Grains separates that four-file source field from a granular event layer, Sample Slicer turns as many as four breaks into mapped voices, Sample Circulator loads or captures two stereo performance loops, and Sample Rings moves eight read heads through as many as 32 concentric file-or-input channel rings.

Workflow

  1. Choose an instrument and set its required output format and REAPER track channel count. Sample Player 16 and Sample Slicer 16 use fixed 16-channel outputs; their 2-channel forms, Sample Doubles, Sample Wavesets 2, Sample Motion 2, Sample Lanes 2, Sample Grains 2, and Sample Circulator use an ordinary stereo track. Sample Wavesets 32, Sample Motion 32, Sample Lanes 32, and Sample Grains 32 use fixed 32-channel tracks.
  2. For Sample Rings, route the eight output lanes to the main speakers, a downstream direct panner, or Output Autogain Stereo/Quad for fold-down monitoring. For Processor Ambi Grain, follow it with an ambisonic decoder.
  3. Load the source file or files and confirm that the expected channels appear, or route input into Sample Circulator or Sample Rings and record its loop captures.
  4. Set the sample window, loop region, direction, pitch, and envelope; define a locus, field, and source trajectory in Sample Motion; draw a four-file lane path in Sample Lanes or Sample Grains; or derive and map slices in Sample Slicer.
  5. Choose the source-storage policy described below, audition the result through the established output path, and save the project.

One-shots and Loops

Sample Player loads one sample and plays it chromatically as a forward or reverse one-shot, wrapping loop, or ping-pong loop. Rate mode provides conventional pitch-linked playback speed, while Stretch keeps timing independent of MIDI pitch; optional host BPM sync derives timing from the entered Sample BPM. Auto Trigger, Layer Retrigger, Poly voices, Free timing, and Omni MIDI reception preserve the original defaults, with Gate, One Shot, Toggle, Restart, Ignore, Mono, Legato, Glide, Host sync, and single-channel reception available when needed. Direct waveform handles and zoom edit the active and loop regions, and a labeled cursor follows every active voice; adjustable loop crossfade suppresses wrap discontinuities. Tune, Fine Tune, Root Note, a resonant multimode filter, proportional ADSR, gain, and velocity response complete the playback controls. Pan is stereo-only; Sample Player 16 maps source lanes directly to matching output lanes.

Break Slicing

Sample Slicer loads four breaks, derives equal or transient slices, and maps each break to a consecutive MIDI range. Its stereo and fixed 16-channel variants share the same editor, three-way project-audio storage, proportional envelopes, two inserts per break, four-strip mixer, and processed AUX return.

Two-Deck Playback and Timing

Sample Doubles loads one mono or stereo file into two independently positioned read heads. Shared varispeed changes pitch and duration together; Deck B can sit at a source-beat offset, drift by a fine speed difference, or move in discrete phase steps. The crossfader, velocity-sensitive Punch and Drag commands, cue triggers, transport commands, and thirteen offset keys are directly sequenceable from s3g Tracker.

Waveset Playback and Distribution

Sample Wavesets derives short pseudo-wavecycles from one mono or stereo recording and plays them chromatically through a Sample Player-style range and loop model. Forward, reverse, wrapping, and ping-pong modes combine with Poly, Mono, and Legato voices. Wavesets 2 uses a fixed stereo output. Wavesets 32 assigns each trigger to a mono channel or stereo pair using sequential, palindrome, reverse, random, or no-repeat random-cycle traversal inside a selectable 2–32-channel active width. Both forms share the same group, repeat, stride, ordering, and waveset processing engine.

Bounded Source Motion and Nested Pulses

Sample Motion scans a mono or stereo recording inside a locus-centered field. Hover, Mirror, Drunk, Zigzag, Forward/Reverse, Moving Loop, and Round Trip provide eight trajectory shapes at ordinary source-relative or absolute Hertz rates. Continuous, Packets, and Motor expose or gate that motion; Freeze, Iterate, Pulser, Doublets, Bounce, and Routed Iterate retrigger it through a four-lane event layer. Sample Motion 2 is stereo; Sample Motion 32 can assign outputs at each note, trajectory turn, or segment event.

Four-File Loop Lanes

Sample Lanes 2 and Sample Lanes 32 load as many as four independently sized files. One normalized read head crosses the four waveform lanes using Down, Up, Triangle, Sine, stepped, seeded-random, or editable Manual breakpoint paths. Crossfade makes lane transitions continuous; Jump selects the nearest loaded lane with a short anti-click slew. Each lane has independent Speed, pitch-preserving Stretch, and a signed wrap Nudge whose seam is visible in the waveform. The wide editor keeps waveforms and the path scope on the left, moves selected-lane timing, transport, and path controls into the right toolbox column, and flattens Voice or Routing into a short footer.

Sample Lanes 32 accepts files with one to sixteen channels. Its ROUTING tab swaps the voice panel for output controls, including a categorical ACTIVE OUT menu from 02 through 32. Preserve Field keeps each source channel on the same-numbered output and leaves absent channels silent. Distribute is an explicit topology change: it folds each voice to mono or stereo and sends it through the shared active-width, traversal, pair-layout, and adjacency allocator. Source path, voice timing, and output topology therefore remain independent choices.

See the Sample Lanes guide for complete shared-loop, independent timing, breakpoint editing, path shaping, routing, preset, automation, and state behavior.

Four-File Granulation

Sample Grains 2 and Sample Grains 32 reuse the four lane waveforms, breakpoint path, MIDI voices, and storage model, then add a clearly separate grain-event layer. Its 1280-by-932 editor keeps a consistent 24-pixel row pitch: source waveforms, the read-head scope, and a three-column Grain Process/Timing/Variation toolbox occupy the left; Source Scan, Grain Source, and Path continuously fill the right column; and Voice or Routing spans both columns as the footer. Stacked LOAD/CLEAR buttons give each waveform more room. The Lanes-specific selected-lane Timing/Stretch toolbox is not shown in Grains. Instead of a simulated grain graph, every sounding grain publishes its actual source window, direction, envelope phase, lane weight, and window gain over a deliberately darker waveform. A faint fill accumulates where grains overlap; medium gray is the elapsed contour, bright gray is the remaining contour, and the white dot with a dark halo is current phase. Contour thickness follows lane weight and luminance follows current windowed gain; a contour broken at a loop or wrap-nudge seam continues at the opposite edge. Matching live grain-event rings appear in the read-head path scope. Scan follows normal playback speed and is conditioned by MIDI note around Scan Root, doubling per octave; Grain Pitch Shift remains independent of both note and scan motion. Freeze holds the Position control, Cloud chooses positions stochastically, and Slice quantizes the scan to 2–32 regions. Density and variable Regular/Scatter timing determine event time; Grain Size and Level Variation, Position Spray with directional bias, Pitch Spray, Reverse Chance, and skewable Parzen, Sine, Hann, Triangle, or Gaussian envelopes determine each event. Source Advance can feed the visible lane path continuously from Scan or step that same path once per grain.

Sample Grains 2 accepts mono and stereo files. CHANNEL MODE defaults to Preserve Origins, retaining a stereo file's left and right sides, and can instead derive Mono Sum, Left, Right, Mid, or Side. MONO SPREAD gives each mono or mono-derived grain a stable position across the stereo output. STEREO LINK keeps both original channels on one trajectory or lets them make independent position, pitch-spray, and reverse decisions. POLYPHONY describes MIDI note ownership rather than audio channel width. The stereo edition does not publish the 32-channel allocator parameters.

The GRAIN PROCESS menu can remain Ordinary, sort regions by sampled loudness, repeat a Stutter anchor, progressively shorten and accelerate a Shrink chain, or schedule a close Doublet. These names intentionally parallel Sample Slicer's Mutate operations, but the mechanisms are separate: Slicer rearranges slice material, while Grains schedules overlapping grain windows. With Source Sync on, the second Doublet advances in source time by its output-time spacing. Only Sample Grains 32 shows the compact ROUTING tab, which reveals the 02–32 active-output menu and allocator; Preserve Field retains a wider source as one coherent grain, while Distribute folds and allocates each grain independently. The allocation unit is always GRAIN, regardless of the selected source scan or lane path.

See the Sample Grains guide for complete source-mode, envelope, lane-path, stereo interpretation, process, routing, preset, automation, and state behavior.

Loop Family

  • Sample Circulator: two loaded-or-captured stereo loops with editable windows, direction and join; Replace, Overdub, and Punch recording; manual or moving crossfade; and a live-source blend.
  • Sample Rings: four independent file-or-upstream-input slots packed into as many as 32 channel rings, with eight angular clocks and free, paired, quad, or Field8 radial formations.

Ambisonic Granulation

Processor Ambi Grain loads 1OA, 2OA, or 3OA ACN/SN3D media. Grain time, direction, rate, and envelope remain shared across all active channels so the encoded image stays coherent.

Sample Storage

Sample Circulator accepts file loading or live input capture and always embeds both stereo loops directly in CLAP project state. The saved source sample rate allows duration-preserving restore into a session running at a different rate. Its fixed capacity is approximately 32 seconds per loop; unlike the longer-form file instruments below, it has no Link or Project storage mode.

Sample Player, Sample Doubles, Sample Wavesets, Sample Motion, Sample Lanes, Sample Grains, and Sample Slicer use the same three-way STORE policy. PROJECT, the default for new instances, copies an unchanged source file in the background to the containing saved REAPER project's effective media directory under s3g Samples, registers that file with the same project, and keeps only a path reference in plug-in state. The effective media directory can be different from the folder containing the .RPP. LINK keeps a reference to the original file without copying it. EMBED writes decoded channel audio directly into CLAP state so the source remains available without any external file.

PROJECT gives small plug-in state and project-managed media, but it requires a saved REAPER project and REAPER's CLAP project-media support. Selecting it in an unsaved project, unsupported host, or context without a containing project leaves the request pending instead of guessing a folder or discarding the current source. Saving the project allows the pending collection to retry automatically. REAPER can relocate a registered file and report its new path when Save As is performed with a copy-media option; an ordinary Save As that does not copy media does not make a second copy.

LINK produces the smallest state but the original path must remain valid. EMBED is the self-contained fallback, but it stores decoded 32-bit floating-point PCM rather than the compressed source file: state cost is approximately channels × frames × four bytes and may be much larger than the file on disk. Hosts can snapshot complete plug-in state for undo when a control is committed, when an effect is bypassed, or when an FX chain changes, so large embedded samples can make those actions pause. That cost is cumulative across Sample-family instances, including instances that are currently bypassed. Prefer PROJECT for normal sessions; reserve EMBED for deliberate self-contained exchange or hosts without project-media support.

PROJECT copies are content-verified and deterministically named from the readable source name plus its SHA-256 digest. Reloading the same unchanged source reuses the existing verified file rather than making another copy. Loading that project-media copy directly also reuses it in place instead of nesting another hash-suffixed copy. A changed external source produces a new copy so an earlier project reference cannot silently change underneath another instance. In an unsaved project the operation remains pending; once the host supplies a project and media path, the copy-or-reuse check runs automatically.

The editor abbreviates long paths and reports either the referenced file size or the decoded STATE size. Missing files remain represented by their unresolved path so they can be restored or relinked later. A restored or otherwise pathless decoded asset remains embedded as a safety fallback while it has no usable locator. Sample Slicer's generated mutations have no original file to link: in PROJECT mode they are written as lossless project media under s3g Samples, while EMBED retains their decoded PCM in state.
